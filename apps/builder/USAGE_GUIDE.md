# Admin Builder 사용 가이드

완벽한 프로세스를 만들기 위한 단계별 가이드입니다.

## 1. 시작하기

### 애플리케이션 실행
```bash
# Windows
start.bat

# Mac/Linux
./start.sh
```

브라우저에서 자동으로 열리지 않으면 http://localhost:5174 접속

## 2. 프로세스 생성 워크플로우

### Step 1: 프로세스 이름 설정
- 상단 헤더의 입력 필드에 프로세스 이름 입력
- 예: "신입사원 온보딩", "경비 지출 보고서", "휴가 신청"

### Step 2: 시작 노드 추가
1. 왼쪽 사이드바에서 **시작** 버튼 클릭 (녹색)
2. 캔버스에 시작 노드가 생성됨
3. 노드 클릭 → 사이드바에서 설명 입력 (선택사항)

### Step 3: 작업 노드 추가
1. 사이드바에서 **작업** 버튼 클릭 (파란색)
2. 노드 클릭하여 선택
3. 사이드바에서 편집:
   - **제목**: 작업 단계 이름 (예: "개인정보 입력")
   - **설명**: 작업 설명 (예: "신입사원의 기본 정보를 입력하세요")
   - **체크리스트**: 확인 항목 추가
     - "추가" 버튼으로 새 항목 생성
     - 텍스트 입력, 필수 여부 체크
     - X 버튼으로 삭제
   - **입력 필드**: 사용자 입력이 필요한 항목
     - 텍스트/파일/날짜 버튼으로 필드 타입 선택
     - 라벨, 플레이스홀더 입력
     - 필수 입력 체크

### Step 4: 노드 연결
1. 시작 노드의 하단 핸들(작은 원)에서 마우스 드래그 시작
2. 첫 번째 작업 노드의 상단 핸들로 드래그
3. 화살표 연결 생성됨
4. 다음 작업 노드들도 순차적으로 연결

### Step 5: 종료 노드 추가
1. 사이드바에서 **완료** 버튼 클릭 (빨간색)
2. 마지막 작업 노드에서 종료 노드로 연결
3. 종료 노드 클릭 → 완료 메시지 입력 (선택사항)

### Step 6: 추적 관리 설정
사이드바에서 다음 항목 입력:
- **부서**: 드롭다운에서 선택
- **업무 유형**: 예: ONBOARDING, EXPENSE, LEAVE
- **담당자 ID**: "생성" 버튼으로 자동 생성 또는 직접 입력
- **담당자 이름**: 예: 홍길동
- **우선순위**: 낮음/보통/높음/긴급
- **마감일**: 날짜 시간 선택
- **예상 소요 시간**: 시간 단위 숫자 입력

### Step 7: 검증 및 내보내기
1. 상단 **JSON 내보내기** 버튼 클릭
2. 검증 오류가 있으면 팝업에서 확인 후 수정
3. 검증 통과 시 JSON 파일 다운로드
4. 파일명: `{프로세스이름}.json`

## 3. 고급 기능

### 조건 분기 사용 (Condition Node)
```
시작 → 작업1 → 조건 → 작업2 (참)
                    └→ 작업3 (거짓)
```

1. **조건** 노드 추가 (노란색)
2. 조건 노드에서 두 개의 출력 핸들 확인:
   - 왼쪽: 참(true) 경로
   - 오른쪽: 거짓(false) 경로
3. 각 핸들에서 다른 작업 노드로 연결
4. 나중에 두 경로를 다시 합치거나 별도 종료 노드로 연결

### 필드 타입별 사용 예시

#### Text 필드
```json
{
  "type": "text",
  "label": "이름",
  "required": true,
  "placeholder": "홍길동"
}
```
**사용 예**: 이름, 이메일, 전화번호, 사번

#### Number 필드
```json
{
  "type": "number",
  "label": "지출 금액 (원)",
  "required": true,
  "placeholder": "0"
}
```
**사용 예**: 금액, 수량, 점수

#### Date 필드
```json
{
  "type": "date",
  "label": "입사일",
  "required": true
}
```
**사용 예**: 날짜, 기간 시작/종료일

#### File 필드
```json
{
  "type": "file",
  "label": "이력서",
  "required": true,
  "validation": {
    "accept": ".pdf,.docx",
    "maxSize": 10485760
  }
}
```
**사용 예**: 문서, 이미지, 증빙 자료

#### Textarea 필드
```json
{
  "type": "textarea",
  "label": "특이사항",
  "required": false,
  "placeholder": "추가로 전달할 사항"
}
```
**사용 예**: 긴 설명, 사유, 메모

## 4. 실전 예제

### 예제 1: 간단한 2단계 승인 프로세스

**구조:**
```
시작 → 신청서 작성 → 완료
```

**설정:**
1. 시작 노드 추가
2. 작업 노드 "신청서 작성" 추가
   - 체크리스트: "신청 사유 명확히 기재" (필수)
   - 필드 1: text, "신청 제목"
   - 필드 2: textarea, "신청 사유"
3. 종료 노드 추가
4. 노드 연결: 시작 → 작업 → 완료
5. 추적 관리 설정
6. JSON 내보내기

**결과:** `samples/simple-approval.json` 참조

### 예제 2: 복잡한 5단계 프로젝트 프로세스

**구조:**
```
시작 → 계획 수립 → 팀 구성 → 자원 할당 → 킥오프 미팅 → 완료
```

**설정:**
1. 시작 노드 추가
2. 작업 노드 4개 추가:
   - **계획 수립**: 목표, 범위 정의
   - **팀 구성**: 팀장, 팀원 배정
   - **자원 할당**: 예산, 장비 배정
   - **킥오프 미팅**: 회의 진행, 회의록 작성
3. 각 작업마다 체크리스트 + 필드 추가
4. 종료 노드 추가
5. 순차적으로 연결
6. 추적 관리 설정 (우선순위: 높음, 예상 시간: 40시간)
7. JSON 내보내기

**결과:** `samples/complex-project.json` 참조

## 5. 검증 체크리스트

JSON 내보내기 전 확인사항:

### 프로세스 구조
- [ ] 시작 노드가 정확히 1개 존재
- [ ] 종료 노드가 최소 1개 이상 존재
- [ ] 시작 노드를 제외한 모든 노드가 입력 연결됨
- [ ] 순환 참조 없음 (노드 A → B → A 형태)

### 작업 노드 내용
- [ ] 모든 작업 노드에 의미 있는 제목
- [ ] 설명 추가 (선택사항이지만 권장)
- [ ] 체크리스트 또는 필드 최소 1개 이상

### 추적 관리
- [ ] 부서 선택됨
- [ ] 업무 유형 입력됨
- [ ] 담당자 ID 입력됨
- [ ] 담당자 이름 입력됨
- [ ] 우선순위 설정됨
- [ ] 마감일 설정됨

## 6. 팁과 트릭

### 노드 배치 최적화
- 드래그로 노드 위치 조정
- 자동 정렬: 위에서 아래로 흐르도록 배치
- 미니맵으로 전체 구조 확인

### 효율적인 작업 순서
1. 먼저 모든 노드를 추가하고 연결
2. 그 다음에 각 노드의 상세 내용 작성
3. 마지막으로 추적 관리 설정

### 재사용 가능한 프로세스 만들기
- 일반적인 프로세스 템플릿 생성
- JSON 파일 저장해두고 필요시 복사
- 업무 유형별로 분류 (HR, IT, 재무 등)

### 오류 방지
- 노드 삭제 시 자동으로 연결도 삭제됨
- 초기화 버튼으로 처음부터 다시 시작 가능
- JSON 내보내기 전 반드시 검증 실행

## 7. User Executor와 연동

### JSON 파일 사용 방법
1. Admin Builder에서 JSON 파일 다운로드
2. `user-executor/samples/processes/` 폴더에 복사
3. User Executor 실행
4. 프로세스 목록에서 선택하여 실행

### 호환성 체크
- 모든 필드 타입이 User Executor에서 지원됨
- 체크리스트 완료 여부 자동 추적
- 파일 업로드 검증 (크기, 형식)
- 진행 상황 실시간 저장

## 8. 문제 해결

### "시작 노드가 없습니다" 오류
→ 녹색 **시작** 버튼으로 시작 노드 추가

### "종료 노드가 없습니다" 오류
→ 빨간색 **완료** 버튼으로 종료 노드 추가

### "노드가 연결되지 않았습니다" 오류
→ 모든 작업/종료 노드가 이전 노드에서 화살표로 연결되어야 함

### "순환 참조가 존재합니다" 오류
→ 노드 A → B → A 형태의 루프 제거 필요

### "담당자 ID가 필요합니다" 오류
→ 추적 관리 섹션에서 담당자 ID와 이름 입력

### 노드 연결이 안 될 때
- 출력 핸들(하단)에서 입력 핸들(상단)로 드래그
- 시작 노드는 입력 핸들 없음
- 종료 노드는 출력 핸들 없음

## 9. 키보드 단축키

- **Delete**: 선택한 노드 삭제
- **Ctrl + Z**: 실행 취소 (미지원 - 초기화 사용)
- **클릭**: 노드 선택
- **드래그**: 노드 이동
- **Shift + 드래그**: 캔버스 이동

## 10. 베스트 프랙티스

### 프로세스 설계
1. **명확한 목표**: 프로세스의 목적을 먼저 정의
2. **단계 최소화**: 불필요한 단계 제거
3. **명확한 이름**: 각 단계에 직관적인 이름 사용
4. **적절한 세분화**: 너무 많거나 적은 단계 지양

### 체크리스트 작성
- 구체적이고 실행 가능한 항목
- 검증 가능한 기준 제시
- 필수/선택 구분 명확히

### 필드 설계
- 필요한 정보만 요청
- 명확한 라벨과 플레이스홀더
- 적절한 필드 타입 선택
- 검증 규칙 추가 (파일 타입 등)

### 문서화
- 프로세스 이름은 명확하게
- 각 단계에 상세한 설명 추가
- 예상 소요 시간 현실적으로 설정
